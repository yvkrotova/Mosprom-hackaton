# LinQ Safety — видеоконтроль промышленной безопасности

Хакатон «Открой Моспром 2026», кейс LinQ. Веб-приложение для специалиста по охране труда, диспетчера и
мастера смены: видео → нейросеть находит людей → правило сценария (человек в опасной зоне) → **одно**
событие на эпизод → тревога с кадром в браузере → журнал.

```
backend/    FastAPI + конвейер анализа (воркер на источник), SQLite, WebSocket. Подробно: backend/README.md
frontend/   интерфейс оператора: статические ES-модули без сборки, их раздаёт backend
linq/       подготовка к LinQ TPU: калибровка, notebook для Jupyter, сравнение и замеры
docs/       статус, замеры, заметки по SDK LinQ, шаги для человека, инструкция по разметке
```

## Запуск

Нужны Python 3.11+ (проверено на 3.12) и, по желанию, Node.js 18+ (только для проверки фронта).

```powershell
cd backend
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env          # здесь же выбирается детектор: DETECTOR=mock|replay|onnx|linq
.\.venv\Scripts\python.exe -m uvicorn app.main:app
```

Откройте **http://localhost:8000** — backend отдаёт и API, и интерфейс. Swagger: http://localhost:8000/docs.
(Linux/macOS — те же шаги, см. [backend/README.md](backend/README.md).)

### Нейросеть YOLOv8s

Положите `yolov8s.onnx` (и, если есть, `yolov8s.pt`) в `backend/models/` — веса в git не хранятся. Получить заново:
`yolo export model=yolov8s.pt format=onnx imgsz=640 opset=12 simplify=True` (в отдельном окружении с ultralytics).
Затем в `backend/.env`: `DETECTOR=onnx`. Это **CPU компьютера, не LinQ** — интерфейс и `/metrics` показывают это явно
(`onnx_cpu`).

### LinQ TPU
Два пути, оба без тихой подмены CPU:
- **Предзаписанные результаты (replay).** В Jupyter организаторов `linq/run_linq_detections.py`
  (обёртка — `linq/notebooks/run_linq_detections.ipynb`) прогоняет видео через программу `.tpu` и пишет JSONL
  schema v2: детекции каждого кадра + метаданные (SHA-256 видео, модель, пороги, время). JSONL прикладывается к
  видео при «Добавить камеру» (или в «Камеры и зоны» → «Изменить»), backend проигрывает его ReplayDetector'ом.
  Интерфейс пишет «Replay — предзаписанные результаты LinQ», время инференса — историческое из записи.
  Формат — [backend/docs/CV_CONTRACT.md](backend/docs/CV_CONTRACT.md), «Replay v2».
- **Живой инференс** — `DETECTOR=linq` (RabbitMQ-протокол организаторов или JPEG-мост через Jupyter),
  см. [docs/LINQ_CONNECT.md](docs/LINQ_CONNECT.md). Нужен VPN.

Без доступа к LinQ ничего не подменяется: ошибка подключения — ошибка источника.

### Демо на тестовых видео (DETECTOR=onnx, TRACKER=bytetrack)

Ролики кладутся в `backend/data/videos/` и `backend/data/storage/videos/` (в git их нет, описание —
`backend/data/videos/manifest.json`). В `backend/.env`: `DETECTOR=onnx`, `TRACKER=bytetrack`,
`DETECTOR_CONF_THRESHOLD=0.1`, `REALTIME_PLAYBACK=true`.
```powershell
cd backend
.\.venv\Scripts\python.exe tools\seed.py --videos     # 4 источника: зоны и правила «зона» + «бег» уже настроены
```
Зоны предложены по превью: поправьте их в «Камеры и зоны», если нужно (у запущенного анализа правка применяется на лету).

Порядок показа:
1. **«Цех: проход, человек уходит от камеры» (te21)** — человек проходит «Проход у станка». Через ~1 с после
   входа в зону приходит **одна** тревога «Человек в опасной зоне». Карточка обновляется, пока он в зоне, и
   завершается, когда выходит. Бега нет: в панели треков скорость ~0.3–0.6 роста/с.
2. **«KTH: бег поперёк кадра»** — 4 пробежки → 4 тревоги «Бег / резкое перемещение». В карточке кадр с красной
   рамкой, траекторией и скоростью ~2 роста/с (это не м/с).
3. **«Цех: проход, люди вдали» (te1)** — рамки держатся без мерцания у нескольких людей (у каждого свой цвет).
   С ~11 с человек входит в «Проход у пресса» → одна тревога.
4. **«Склад: обрушение стеллажа»** — люди слишком мелкие для YOLOv8s: тревог нет. Честный пример ограничения детектора.
5. «Журнал» → фильтр «Бег / резкое перемещение»; «Статистика» → замеры и плашка «ONNX · CPU (не LinQ)».

Без модели — заглушка: `DETECTOR=mock`, `python tools/seed.py --demo` (вход в зону) или `MOCK_SCENARIO=run_fast_movement` (бег).
Замеры, проверка трекера и порога — [docs/BENCHMARKS.md](docs/BENCHMARKS.md).

### Ограничения
- Инференс пока на CPU (~9 кадров/с), не на LinQ (см. выше).
- Скорость бега — в ростах человека в секунду при неподвижной камере. Порог 1.7 подобран на роликах с бегом и быстрым шагом.
- YOLOv8s (COCO) плохо видит очень мелких и сидящих людей (видно на te21 и складе).
- Разметка тестовых роликов — черновик ([docs/VIDEO_LABELING.md](docs/VIDEO_LABELING.md)).

## Ручная проверка интерфейса

Снимки экранов (1586×992) — `frontend/design/screenshots/`. Перед проверкой: backend запущен, добавлены 1–2 камеры.

**Общее**
- Круглая кнопка ««» сворачивает меню до иконок (подсказки при наведении); анализ на «Мониторинге» не прерывается.
  Состояние меню сохраняется после перезагрузки.
- «Настройки» → тема (тёмная по умолчанию / светлая), имя оператора, громкость. «Звук включён/выключен» — только звук уведомлений.
- Остановите backend → сверху баннер «Нет связи с сервером», экран сереет; запустите — баннер уходит сам.

**Мониторинг**
- «Камер: N» → 1…9: 1 — одна, 2 — две в ряд, 3 — 3×1 или 2+1, 4 — 2×2, 5–6 — 3×2, 7–9 — 3×3; пропорции кадра сохраняются.
- Пустая ячейка: «Выбрать камеру» / «Добавить камеру». Одна камера автоматически в две ячейки не ставится.
- Метка ячейки: «Запись» (файл), «Прямой эфир» (поток), «Replay — предзаписанные результаты LinQ» (запись LinQ),
  «Нет сигнала» с «Переподключиться» при ошибке.
- Значок раскрытия → камера на всю область, «←» — назад к сетке; ещё раз — полный экран, Esc — выход.
- Панель событий: «Все»/«Новые», счётчик непросмотренных; клик по карточке выделяет её → «Смотреть эпизод»
  (отмечает просмотренным, но не подтверждает); «⋮» → «Открыть в журнале», «Перейти к камере»; «Все события» → журнал.
- Нет камер — предложение добавить; нет событий — «Событий пока нет».

**Журнал нарушений**
- «Сегодня / 24 часа / 7 дней / Всё время» меняют поля «С»/«По»; ручной ввод «По» раньше «С» — пояснение у поля,
  выборка не меняется.
- Восемь фильтров работают совместно, без «Применить»; список зон зависит от камеры, есть «Весь кадр».
- «Найдено N событий» и сортировка «Сначала новые/старые» — по всей выборке; пагинация — по данным.
- «Скачать CSV» — вся выборка с фильтрами (UTF-8 с BOM, «;»), кнопка блокируется на время выгрузки.
- Клик по строке → подробности: видео эпизода (с начала эпизода) или кадр с пояснением, комментарий,
  «Подтвердить нарушение» / «Ложное срабатывание» / «Передать мастеру»; после сохранения строка обновляется,
  фильтры, страница и прокрутка остаются.
- Фильтр без результатов → «По выбранным условиям событий не найдено» + «Сбросить фильтры».

**Камеры и зоны**
- «Новая зона» → клики по кадру → замыкание кликом по первой точке или «Завершить контур»; «Отменить точку»
  активна, только когда есть что отменять. Точки ставятся только внутри кадра.
- Перетаскивание точек, «Переместить» — сдвиг зоны целиком без выхода за кадр.
- Самопересекающийся контур или пустое название → «Сохранить изменения» показывает ошибку у зоны, черновик остаётся.
- Переключатель в строке зоны и «Контроль включён» — одно состояние. «Удалить зону» помечает её, «Отмена» возвращает.
- «Сохранить изменения» — одной операцией; у запущенного анализа изменения применяются через пару секунд.
- Смена камеры, уход со страницы или закрытие вкладки с несохранёнными изменениями — подтверждение.
- «Изменить» камеру: участок, адрес (при смене — предупреждение проверить разметку), привязка replay-файла.

**Статистика**
- Периоды и камера меняют шесть показателей; «Ждут» + «Подтверждено» + «Ложных» = «Нарушений за период».
- «Открыть в журнале» — журнал с теми же границами времени и камерой.
- Блок замеров: метка среды по фактическому детектору («ONNX · CPU (не LinQ)» + предупреждение; replay —
  историческое время LinQ и текущая скорость воспроизведения раздельно); для «Все камеры» — переключатель камер.
- «Печать отчёта» → светлый лист без меню и кнопок: название, период, камера, время, шесть показателей, замеры.
- «Демонстрационные данные» — только если события получены заглушкой (mock).

**Режим replay**
- «Добавить камеру» с видео и JSONL этого видео → метка «Replay — предзаписанные результаты LinQ», события как обычно.
- JSONL от другого видео → камера в ошибке «Запись не соответствует видео: SHA-256 …».
- Повторный запуск той же записи не дублирует события в журнале.
