составлена по контактным листам и траекториям детектора, видео целиком не просмотрено.
Перепроверка — [VIDEO_LABELING.md](VIDEO_LABELING.md). После проверки перезапустите команды ниже.

Условия: детектор YOLOv8s ONNX (`backend/models/yolov8s.onnx`) на CPU, onnxruntime 1.31.0, Windows 11,
AMD64 Family 25 (ноутбук), Python 3.12; analysis_fps = 10; вход сети 640×640, batch 1;

## Трекеры: IoU против ByteTrack

`python tools/track_videos.py --render` (JSON — `backend/data/videos/track_stats.json`, рендеры и скриншоты —
`backend/data/videos/rendered/`). «Обрывы» — новый трек начался в пределах роста от места, где другой
пропал меньше 1.5 с назад (оценка переключений ID без разметки).

| ролик | людей (по превью) | IoU: ID / обрывы / ср. трек | ByteTrack: ID / обрывы / ср. трек |
|---|---|---|---|
| te1 | 4–6 видимых | 8 / 1 / 4.6 с | **5 / 0 / 7.9 с** |
| te21 | 2 (+ сидящий оператор) | 2 / 0 / 5.7 с | **2 / 0 / 5.6 с** |
| accident | мелкие, неуверенные | 2 / 0 / 0.7 с | 0 / 0 / — |
| kth_running | 4 пробежки | 12 / 8 / 0.3 с | **4 / 0 / 0.9 с** |

По скриншотам: скачков ID и рамок нет. Замечено:
- **te21:** детектор не видит **сидящего у станка оператора** (поза сидя, частично закрыт);
- **te1:** не видны двое у станков слева; трек #11 справа, вероятно, — синяя бочка, а не человек
  (уверенность ~0.3–0.5). В правила такие треки не проходят из-за `min_confidence` 0.4.

В ByteTrack добавлен этап «1b». Если рамки соседних кадров уже не пересекаются (бег при 5–10 кадрах/с),
детекция сопоставляется по расстоянию центров в ростах. Без него бегущий в KTH рвётся на 3 трека за пробежку.

## Порог скорости бега (run_fast_movement)

`python tools/dump_track_speeds.py --video <id> --out speeds.csv` (CSV — `backend/data/videos/speeds/`).
Скорость — смещение ног / высота рамки / Δt, «ростов в секунду», сглажена EMA.

| ролик | что | медиана, роста/с | максимум |
|---|---|---|---|
| kth_running | 4 пробежки | 1.80 / 1.98 / 2.16 / 2.05 | 2.17 / 2.03 / 2.19 / 2.14 |
| te21 | ходьба от камеры | 0.29 | 0.58 |
| te1 | ходьба к камере, люди вдали | 0.05–0.29 | 0.37 |

**Выбран speed_threshold = 1.5.** Обоснование по цифрам:
- в 2.6 раза выше максимума ходьбы (0.58);
- на ~20% ниже самой медленной медианы бега (1.80).

При 1.8 при 10 и 15 кадрах/с терялась первая пробежка: пока EMA разгоняется, её медиана ровно 1.8.

**Порог подтверждён частично:**
- бег есть только в одном ролике (KTH, 160×120);
- ходьба — только вдоль оптической оси, где перспектива занижает скорость. Боковая ходьба (0.6–1.0)
  и быстрый шаг (до ~1.3) в роликах не проверены — нужен ролик с такой ходьбой.

Для KTH в правиле заданы `confirm_window_s = 0.4` и `min_track_age_s = 0.3`. Человек в кадре ~1 с, и при
параметрах по умолчанию (0.5 + 0.8 с) эпизод не успевает подтвердиться. Для обычной камеры
наблюдения, где бегущий в кадре дольше 1.5 с, оставлены значения по умолчанию.
