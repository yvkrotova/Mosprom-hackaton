## Маршрут (из PDF «Процедура подготовки…»)
1. `[Модель ONNX] → (SDK: квантование, компиляция) → [Программа для TPU]`. Программа содержит топологию и веса.
2. `[Данные] → (наш препроцессинг) → [входной тензор] → (API LinQ: передача, инференс) → [выходной тензор] → (наш постпроцессинг)`.
3. Пре- и постпроцессинг — на стороне приложения. У нас это `yolo_common.letterbox` и `postprocess`,
   общие для ONNX и LinQ.

## Удалённый сервис (из PDF «Инструкция удалённому сервису…»)
- Доступ: VPN (OpenVPN, конфиг из рассылки, логины капитанам) → Jupyter `http://hackathon.lin-q.ru/`.
- В Jupyter папки `examples` (пример инференса resnet50 на TPU, `example.ipynb`) и `packages`.
- В примере (по скриншоту) видно:
  - `LOGIN = 'hackathonXXXXX'` (свой логин);
  - `PROGRAM_DIR = os.path.join('/auto/cache', LOGIN)`, `PROGRAM = 'torch_resnet50_b1_o5_h1m.tpu'`, `!cp {PROGRAM} {PROGRAM_DIR}`.
  Значит:
  - программа TPU — файл **`.tpu`**, компилируется **локально** и загружается в Jupyter;
  - инференс выполняется **из Jupyter** с логином команды.
- Суффиксы `_b1_o5_h1m` в имени, вероятно, параметры компиляции (b1 — batch 1?). **Неизвестно** — по SDK.

## Модель: что проверено у нас
`linq/check_onnx_ops.py` по `backend/models/yolov8s.onnx`:
- opset 12, вход `images` [1, 3, 640, 640], выход `output0` [1, 84, 8400], все формы статичные, 234 узла;
- операции: Conv 64, Sigmoid 58, Mul 58, Concat 17, Split 8, Add 8, Reshape 8, MaxPool 3, Resize 2,
  Transpose 2, Slice 2, Sub 2, Softmax 1, Div 1;
- хвост — декодирование DFL: Reshape → Transpose → Softmax → Conv → Slice/Sub/Add/Div → Concat → Mul → Concat.

**План, если SDK что-то не поддерживает** (по порядку):
1. Переэкспорт из `yolov8s.pt` с параметрами SDK: `linq/export_onnx.py` (отдельное окружение с ultralytics).
2. Отрезать декодирование головы (DFL, Softmax, Concat в конце), выводить сырые выходы трёх голов и
   декодировать на CPU (дописать `decode_heads` в `yolo_common.py`).
3. Запасной вариант — yolov8n.

## Главный риск квантования, найденный тестом
В выходе `[1, 84, 8400]` в одном тензоре лежат координаты (0–640 пикселей) и оценки классов (0–1).
При int8 с **одной шкалой** на тензор шаг квантования ~5 пикселей, и уверенность 0.9 обращается в 0:
детекций не остаётся (`test_quantize_dequantize_roundtrip_and_decode`). Нужна одна из мер:
- компилятор квантует выход поканально или оставляет его во float;
- координаты и классы — отдельные выходы (отрезать последний Concat);
- декодирование головы переносится на CPU (п. 2 выше).
